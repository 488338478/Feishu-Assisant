# 群聊记录按需检索设计

## 目标

机器人只在当前问题需要群聊背景时检索当前群的历史消息。普通问题不附带群聊记录，减少噪声和上下文占用；涉及前文指代、回复链或信息缺失时，由 AI 自主调用检索工具补齐背景。

## 硬性边界

- 检索范围由宿主绑定为当前 `chat_id`，模型不能传入或覆盖群 ID，禁止跨群检索。
- 私聊内容不进入群聊检索库，群聊内容也不进入私聊上下文。
- 关键词、指代词和回复关系只作为参考信号，不作为允许或拒绝检索的条件。
- AI 可以在没有关键词命中的情况下，根据信息完整度自主决定检索。
- 检索服务可以查找、过滤、排序和排版消息，但不得总结、改写、拼接或润色消息正文。
- 返回消息中的 `content` 必须来自保存的原始消息；发送人和时间由宿主添加。

## 数据流

### 消息采集

群消息事件到达后，先进行事件去重和范围校验，再保存以下字段：

- `chat_id`
- `message_id`
- `sender_id` 与可显示名称
- `sent_at`
- `reply_to` 或 thread/root message ID
- `content_type`
- 原始 `content`
- 编辑、撤回和删除状态

未 @ 机器人的群消息只进入当前群的检索库，不触发 AI 回复。撤回或删除事件会同步使消息不可检索。

### AI 决策

机器人被触发后，AI先读取用户问题和现有群会话。提示词说明群聊检索适用场景，但不给出机械的关键词门控。典型参考信号包括：

- 用户明确要求结合群里、刚才或之前的讨论；
- 消息引用或回复了其他群友；
- 问题存在无法从当前上下文解析的主体、时间、项目或指代；
- AI认为查阅当前群记录能显著降低回答的不确定性。

现有信息已经足够时，AI可以不检索，即使命中了参考词。

### 检索工具

向 AI 暴露两个能力：

```text
search_current_group_history(query, time_range?, sender_ids?, thread_id?, limit?)
expand_group_message(message_id, part)
```

`chat_id` 不属于工具参数，由宿主根据当前事件注入。策略层在执行前再次校验消息所属群，防止通过 message ID 绕过群边界。

第一次检索返回相关性最高的消息。AI可以调整查询、时间范围、发送人或回复链再检索一次。默认每次回答最多两轮检索，配置可热修改。

## 返回格式与原文完整性

普通消息使用紧凑文本格式：

```text
[09:32 张三] 发布日期先定在周五
[09:35 李四] 周五资源不够，建议顺延到下周一
[09:41 王五] 等测试结果出来再决定
```

方括号内的时间和姓名是宿主生成的元数据。右侧正文保持原始 `content`，包括标点、空格、换行、错别字和语气，不经过第二个模型处理。多行正文从首行前缀后开始并保留原换行。

检索索引可以使用分词、向量或规范化副本计算相关性，但最终输出必须回源到不可变的原始正文，不能输出索引中的规范化文本。

群聊记录作为不可信引用材料包裹，不能把群友消息中的指令当作系统指令或工具授权。

## 长度管理

长度管理优先减少低相关消息，不轻易截断自然聊天：

- 自然聊天软阈值：默认 `3000` 字符。阈值以内完整返回。
- 非自然内容软阈值：默认 `2000` 字符。适用于转发记录、日志、堆栈、JSON、大段代码或高度重复文本。
- 单条消息硬阈值：默认 `12000` 字符。超过后按原文字符区间分片。
- 单轮检索总预算：默认约 `6000 tokens`。
- 单次回答最多两轮检索。

自然聊天判断使用内容类型和结构特征，例如换行密度、日志前缀、代码比例、JSON结构、转发卡片类型和重复行。判断不确定时按自然聊天处理。

消息需要分片时，片段是原文的连续子串，不进行摘要：

```text
[09:32 张三｜原文片段 1/4｜可继续展开] <原文连续内容>
```

AI通过 `expand_group_message` 读取后续片段。回复链和强相关自然长消息优先获得预算；预算不足时先减少其他低相关消息。

所有阈值、检索轮数和总预算进入运营配置并支持热修改。

## 日志和可观测性

每次决策记录可核验信息，不记录模型私有逐字推理：

- 是否调用群聊检索；
- AI给出的简短检索理由；
- 查询词、时间范围、发送人和回复链过滤条件；
- 命中数量、返回消息 ID、字符数和 token 估算；
- 是否发生分片、展开或预算截断；
- 群范围策略校验结果。

日志页面默认只展示消息 ID 和长度等元数据；查看原文需要相应运营权限，并留下审计记录。

## 失败处理

- 检索不可用时，AI明确说明缺少群聊背景，并基于已有信息回答或向用户追问。
- 没有命中时，不制造群聊结论。
- 消息已撤回、删除或无权访问时，返回不可用状态，不回退到历史缓存原文。
- token 预算不足时，返回已选中的完整消息或明确标记的原文分片，不生成摘要替代。

## 验收标准

- 完整的普通问题不会触发群聊记录检索。
- 信息缺失但没有关键词时，AI仍可以自主检索。
- 命中关键词但上下文充分时，AI可以不检索。
- 工具无法检索当前群以外的消息，包括伪造 message ID 的情况。
- 正常消息按 `[时间 姓名] 原文` 返回，正文逐字符等于保存的原始内容。
- 自然聊天在 `3000` 字符以内不被截断。
- 超长消息只进行确定性原文分片，不经过摘要模型。
- 撤回或删除的消息不再出现在检索结果中。
- 每次检索均可在后台追踪原因、范围、命中和上下文预算。
