# 飞书云文档图片工作流设计

## 目标

让飞书助手能够安全地处理图片：读取飞书消息中的图片并交给 Claude/DeepSeek 进行视觉理解，读取飞书云文档中的图片，在用户明确要求时向云文档插入图片或删除图片块。

本方案只覆盖飞书云文档和飞书消息图片，不扩展到本地 Markdown、Word 或其他云盘文件编辑。

## 现状与约束

- 当前 Python 宿主接收的主要是文字消息，云文档正文由 Claude 通过 `lark-cli` 操作。
- `lark-cli` 已提供 `docs +media-insert`、`docs +media-preview`、`docs +media-download`，以及带 block ID 的 `docs +fetch` 和 `docs +update`。
- docs profile 默认禁止本地文件 `Read`，不能为了识图而开放整个工作目录。
- Claude CLI 当前统一通过 `_run_claude` 调用，DeepSeek 4.1 也走该工具链；图片输入必须经过受控工具传递，不能假定仅设置模型名就自动获得图片。
- 删除文档内容是高风险操作，必须区分“识别/建议删除”和“实际删除”。

## 推荐架构

### 1. 图片接收与临时存储

事件层识别飞书图片消息，保留 `chat_id`、`message_id`、`sender_id`、`image_key` 和消息时间等元数据。宿主使用飞书消息资源接口下载图片到 `ASSISTANT_DATA_DIR/media/inbox/<message_id>/` 下的临时文件，文件名和路径由宿主生成，不接受模型提供的任意路径。

下载失败时不启动视觉推理，向用户返回可读错误。成功处理后按生命周期清理文件；正在运行的请求和短期重试期间保留，异常退出时由下次启动的清理任务回收过期目录。

### 2. 受控 MCP 图片工具

新增独立的图片 MCP 服务，只暴露宿主登记过的图片引用，不暴露任意文件系统路径。工具接收图片引用，返回原始图片的标准 MCP image content，以及必要的文件名、尺寸和来源元数据；默认不缩放、不压缩、不生成预览图。

模型只能读取当前请求已登记的图片，不能枚举目录、读取任意服务器文件或从图片工具绕过 docs profile 的本地文件策略。

运行时在 prompt 中注入当前请求的图片引用和用途说明；图片内容通过 MCP 工具返回给模型。模型没有图片引用时不能自行猜测服务器路径。

### 3. 云文档图片读取

模型处理已有云文档图片时，按以下顺序执行：

1. 用 `docs +fetch` 获取目标范围和最新 block ID。
2. 从 `<img token="...">` 提取资源 token。
3. 使用 `docs +media-preview` 或 `docs +media-download` 获取图片。
4. 通过受控图片工具交给模型分析。

图片识别只读文档和媒体，不修改文档。每次写操作前必须重新读取最新 block ID，避免使用过期块 ID。

### 4. 插入图片

用户明确要求插入图片时，模型先确认目标文档和插入位置；位置不明确时默认文末，但必须在回复中说明。图片来源支持：当前消息图片、云文档已有图片复制、用户给出的图片文件/URL（在宿主允许的范围内）。

实际写入使用 `docs +media-insert` 或 `docs +update block_insert_after`。写入完成后重新 fetch 验证图片 block、文档位置和返回的资源 token，并向用户报告实际结果。

### 5. 删除图片

删除流程必须拆成两步：

1. 识别阶段：读取最新文档 block，列出候选图片位置、相邻文本或图片描述，并询问用户确认。
2. 执行阶段：用户明确确认后重新 fetch，确认目标仍是同一图片 block，再调用 `docs +update --command block_delete`。

不能通过 `str_replace` 删除图片，也不能因为模型认为图片重复、无关或低质量就自动删除。用户拒绝或目标发生变化时不执行写入。

### 6. 权限与审计

- 识图：需要读取当前消息或文档媒体的权限。
- 插入：需要当前用户对目标文档的编辑权限，并经过现有 Claude 工具权限层。
- 删除：需要编辑权限、用户明确确认，并记录文档 token、block ID、操作者 open_id、操作类型和结果。
- admin bypass 只绕过 Claude 工具确认，不绕过飞书文档权限、Linux 权限或删除前的业务确认。
- 临时图片不得写入会话历史或普通审计正文，只记录引用、尺寸、来源和生命周期结果。

## 错误处理

- 无图片资源或下载失败：说明具体资源和原因，不进行模型推理。
- 模型不支持图片输入：返回“当前模型无法读取图片”，不伪造识别结果。
- 图片格式/尺寸超限：提示限制并停止，不偷偷压缩或改用预览图；只有用户明确要求时才另行处理图片。
- 文档 block 已变化：放弃旧写操作，重新读取并要求用户确认新的删除目标；插入操作重新定位锚点。
- 飞书返回权限不足：停止重试，说明需要的文档/媒体权限。

## 测试范围

- 图片消息事件能够解析 image key 并绑定发送者、群和消息 ID。
- 非法或未登记路径不能通过图片 MCP 工具读取。
- MCP 工具返回标准图片内容，且清理任务不会删除活动请求文件。
- 插入操作验证文档 ID、锚点和图片参数；写入后验证流程使用新 block ID。
- 删除操作在未确认、确认人无权限、block 已变化时均不执行。
- Claude/DeepSeek 模型能力通过适配层测试覆盖；真实飞书图片和文档写入留给服务器验收测试。

## 不在本次范围

- 本地 Markdown/Word 文档的图片编辑。
- 自动生成图片或图像编辑。
- 对整篇云文档做视觉版式重排。
- 绕过飞书权限的后台删除。
